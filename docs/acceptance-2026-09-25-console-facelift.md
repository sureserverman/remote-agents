# Acceptance: the console facelift

Measured 2026-09-25 on this host (tmux 3.4, Textual 8.2.8) for the console-facelift master plan
(`2026-09-25-console-facelift-master-plan`, sub-plans 1–3). The design is the Claude Design
handoff "Console facelift"; its README and mock live beside the plan in the vault.

## How it was captured

- **The live console.** `tests/live/test_console_facelift.py` runs a private `remote-agents`
  console under its own `TMUX_TMPDIR`, entered from a bare shell in an outer tmux pane of the
  size under test, with a live Claude reading (the status-line hop's own file) and one managed
  session. It writes `build/facelift-captures/live/{200x50,100x30}.{txt,svg}`: the whole outer
  pane, bar included, as text and as an SVG rendered from the pane's own colours.
- **The mock.** `scripts/render-handoff-mock.py` renders the handoff's HTML once per Tweak
  state (session selected or not, bar full or compact, F11 shown or not). It pins each state by
  rewriting the mock's template flags in a scratch copy, and screenshots it with headless
  Chromium from the Playwright browser cache. Output:
  `build/facelift-captures/mock/*.png`. No Playwright package is installed; only its browser.
- Neither is committed: both are regenerated by the two commands above.

## The cell budget

| | Design | Measured, before | Measured, after |
|---|---|---|---|
| 200x50: left / right | 119 / 80 | 107 / 92 | 119 / 80 |
| 200x50: sessions / limits / feed rows | 15 / 7 / rest | 21 / 10 / 16 | 15 / 7 / 25 |
| 100x30: left / right | 60 / 39 | 57 / 42 | 59 / 40 |
| 100x30: limits rows | its stacked content | 3 (clipped) | 6 to 8, whole |

"Before" is the build before sub-plan 3's Task 2.3. The 60/40 split was applied at build time,
often at 80x24 before any client attached, and tmux rescaled it unevenly. The console now
re-applies its layout on every client attach (`client-attached`) and window resize
(`window-resized`; `client-resized` runs before the window has its new size, measured). The
limits pane asks tmux for exactly the rows it draws. At 100 columns the README's "39" and
the measured 40 are the same 60% split, counted differently.
